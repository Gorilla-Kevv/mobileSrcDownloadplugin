# 五、分平台适配策略

各平台的风控强度、数据结构、登录依赖差异极大，因此适配策略按"**通用能力 + 平台特化**"两层组织：
通用层负责请求头、短链展开、降级；平台层负责字段抽取与登录态注入。

## 5.1 通用适配层（所有平台共享）

| 能力 | 实现 | 作用 |
| --- | --- | --- |
| UA 池 | 桌面 Chrome / 移动 Safari / `facebookexternalhit` / Googlebot | 平台对爬虫 UA 常返回更"干净"的 DOM |
| 短链展开 | HEAD 取 `Location`，失败时 GET 跟随重定向 | `xhslink` / `t.co` / `youtu.be` / `b23.tv` / `v.douyin.com` / `vm.tiktok.com` |
| Referer 注入 | 每个平台解析器自带 Referer，写入 `MediaItem.headers` | 突破防盗链（下载直链时同样携带） |
| 移动版改写 | Facebook 等自动改写到 `m.facebook.com` | DOM 更精简、风控更弱 |
| Cookie 注入 | `ParseContext.cookieProvider(platform)` | 用户提供的登录态，仅本地使用 |
| 降级链 | 本地 → 公开接口 → 远端服务 → 通用解析 | 单点失效不影响整体可用 |

## 5.2 平台特化策略

### Instagram
1. **有 Cookie**：`/p/{code}/?__a=1&__d=dis` → `video_versions[]`（多清晰度）+ `image_versions2.candidates[]` + `carousel_media[]`（多图逐个展开）。
2. **无 Cookie**：`/p/{code}/embed/captioned/` → `video_url` / `display_url` / `<img class="EmbeddedMediaImage">`。
3. **兜底**：官方 oEmbed → 仅缩略图，返回 `warning` 引导补充 Cookie。
4. 适配要点：短链 `instagr.am` 需先展开；作品 ID 用 `(?:p|reel|reels|tv)/([A-Za-z0-9_-]{5,})` 提取。

### X (Twitter)
1. 从 `/status/(\d+)` 提取推文 ID，推导 guest token：`((id/1e15)*π).toString(36)` 去掉 `.` 与 `0`（JVM 无 `Double.toString(radix)`，内核自行实现了进制转换）。
2. 请求 `cdn.syndication.twimg.com/tweet-result`，带 `Referer: https://platform.twitter.com/`。
3. 取 `mediaDetails[].video_info.variants[]` 中 `content_type` 含 `mp4` 的项，按 `bitrate` 降序；图片取 `photos[]`，追加 `?format=jpg&name=orig` 拿原图。
4. 适配要点：该接口无需登录，是当前 X 侧最稳的公开入口。

### 小红书
1. 详情页内联 `window.__INITIAL_STATE__`。**不使用严格 JSON 解析**：该结构含 `undefined` 字面量与尾随逗号，严格解析会整体失败；改用字段级正则 + 括号配对截取。
2. 视频：`stream.h264[].masterUrl` + `backupUrls[]`；图集：`imageList[].urlDefault`，**去掉 `?imageView2...` 裁剪参数即原图**。
3. 补充域名正则兜底：`sns-video*.xhscdn.com/*.mp4`、`sns-webpic*.xhscdn.com/*`。
4. 适配要点：`xsec_token` 参数会被归一化保留（不在跟踪参数黑名单内）；完整图集需登录态。

### Facebook
1. 统一改用移动版页面，按优先级收集：`hd_src_no_ratelimit` > `hd_src` > `sd_src_no_ratelimit` > `sd_src` > `playable_url` > `og:video`。
2. 补充 `video.f*.fbcdn.net/*.mp4` 正则兜底；图片取 `og:image` 与 `scontent.f*.fbcdn.net` 。
3. 适配要点：**强登录依赖**，无 Cookie 时大概率只有封面，此时返回带 `warning` 的结果而非直接失败。

### TikTok
1. 详情页内联 `__UNIVERSAL_DATA_FOR_REHYDRATION__`（兼容 `SIGI_STATE`）。
2. 优先 `bitRateInfo[].PlayAddr.Url`（通常无水印），其次 `playAddr` / `downloadAddr`。
3. 图文作品取 `imagePost.images[]`（`p*-sign.tiktokcdn.com`）。
4. 适配要点：短链 `vm./vt.tiktok.com` 先展开；地区限制会直接拿不到页面，归入 `retryable`。

### 抖音
1. **通道一**：旧版分享接口 `iesdouyin.com/web/api/v2/aweme/iteminfo/?item_ids=`，返回干净 JSON，成功率最高（随时可能下线，保留是因为它最省事）。
2. **通道二**：详情页 `window._ROUTER_DATA`（兼容 `RENDER_DATA`），取 `video.play_addr.url_list`。
3. 去水印：URL 中的 `playwm` 替换为 `play`。
4. 适配要点：`v.douyin.com` 短链必须先展开才能拿到 aweme id。

### 哔哩哔哩
1. `view` 接口取 `cid / title / owner / pic`（不需要签名）。
2. `playurl` 自 2023 起强制 **WBI 签名**，内核完整实现：
   `nav` 取 `img_key + sub_key` → 乱序表重组 32 位 mixin key → 参数排序 + `wts` + `md5(query + mixin_key)` 得 `w_rid`。
3. 优先 `fnval=1` 的 `durl[]` 单一流（下载最省事）；只有 DASH 时返回视频轨 + 音频轨，由下载器合并。
4. 适配要点：`b23.tv` 短链先展开；高码率需登录态。

### 微博
1. `m.weibo.cn/statuses/show?id=` JSON 接口优先；失败则解析 `m.weibo.cn/detail/{id}` 内联 `$render_data`。
2. 视频：`page_info.urls.mp4_720p_mp4 / mp4_hd_mp4 / mp4_sd_mp4`；图片：`pics[].large.url`（`wx*.sinaimg.cn`）。
3. 适配要点：需带 `MWeibo-Pwa: 1` 与 `X-Requested-With` 头，否则返回网页而非 JSON。

### YouTube
1. 客户端硬编码签名算法不可持续（`nsig/sig` 频繁变更），改为**公开中继实例**：依次尝试 Piped 实例列表的 `/streams/{videoId}`。
2. 取 `videoStreams[]`（合并流，直接可播）与 `audioStreams[]`（纯音频）。
3. 用户自建 cobalt 时，解析内核会优先走远端兜底链路。
4. 适配要点：中继实例稳定性不由本应用保证，UI 会提示"通过公开中继实例解析"。

### 通用网页（未覆盖站点）
`og:video:url` → `og:video` → `twitter:player:stream` → DOM 中的 `<video>/<source>` → JSON 中的 `.mp4/.m3u8` → `og:image`，并标注"通用解析，清晰度与完整性不保证"。

## 5.3 失败与降级策略

| 失败类型 | 处理 |
| --- | --- |
| 平台不支持 / 未开启监听 | 直接放弃，不发请求（省电、省流量） |
| 短链展开失败 | 用原 URL 继续尝试 |
| 本地解析拿不到资源 | 依次降级：远端服务 → 通用解析 |
| 需要登录 | 返回 `warning` 或抛带明确文案的 `ParseException`，UI 引导配置 Cookie |
| 网络错误 / 被风控 | 标记 `retryable=true`，UI 提供"重试" |
| 页面结构变更 | 解析器抛异常，日志打点标记解析器 ID，便于单独修复该平台 |

## 5.4 维护策略

- 每个平台解析器独立成类，互不影响；
- 解析结果携带 `resolverId`（如 `xhs-local-v1`），出现大面积失败时可快速定位是哪个解析器需要更新；
- 各解析器内部普遍采用"**多字段正则 + 多来源兜底**"，对页面小幅改版有容错；
- 用户在设置页可随时启用远端解析服务，本地解析器失效期间仍能正常使用。
