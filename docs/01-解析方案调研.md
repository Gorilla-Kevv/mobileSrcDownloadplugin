# 一、网址解析方案调研与整合

> 目标：在 Android 端实现"复制链接 → 自动识别 → 解析出可下载媒体直链 → 下载"。
> 约束：解析能力与下载器均自行实现，不依赖第三方下载 SDK。

## 1.1 现有方案全景

| 方案 | 形态 | 覆盖平台 | 能否直接用于 Android | 评价 |
| --- | --- | --- | --- | --- |
| **yt-dlp** | Python CLI，1000+ extractor | YouTube / X / Instagram / TikTok / Facebook / B站 … | ❌ 不能内嵌（需 Python 运行时） | **算法参考基准**：几乎所有平台解析思路都源出于此 |
| **youtube-dl** | Python CLI（已停更） | 同上 | ❌ | 只作历史参考 |
| **gallery-dl** | Python CLI，偏图集 | Instagram / 小红书 / Twitter / Pixiv | ❌ | 图集类站点的字段命名参考 |
| **cobalt** | Node 服务 + 公开 API（AGPL-3.0） | YouTube / X / Instagram / TikTok / Reddit / B站 / SoundCloud | ⚠️ 需自建或依赖公共实例 | **最佳远端兜底**，协议简单、可自托管 |
| **Piped / Invidious** | 自建 YouTube 前端 + API | YouTube | ✅ 走 HTTP API | YouTube 的可行路径（免签名） |
| **Chaquopy / Termux** | Android 内嵌 Python | 同 yt-dlp | ⚠️ 可行但包体 +50MB、启动慢、合规风险 | 不采用 |
| **平台官方公开接口** | oEmbed / syndication / 移动版 JSON | X、Instagram、微博、B站 | ✅ | **主力方案**，无需登录、稳定 |

## 1.2 整合后的技术选型

采用**"本地直连为主、公开接口为骨架、远端服务兜底"**的三级结构：

```
L0 本地直连解析（Kotlin 自研，主力）
    ├─ 平台移动版/桌面版页面的内联 SSR 数据（__INITIAL_STATE__ / _ROUTER_DATA / UNIVERSAL_DATA）
    ├─ 平台公开接口（X syndication、B站 web-interface、微博 m.weibo.cn）
    └─ OpenGraph / DOM 兜底（og:video、<video src>）
L1 登录态增强（用户提供的 Cookie，本地保存，不外发）
L2 远端解析服务（用户自建 cobalt / yt-dlp 服务端，或公共实例）
L3 通用网页解析器（未覆盖站点的尽力而为）
```

**为什么这样选：**

1. **yt-dlp 不能直接搬**，但它的 extractor 本质是"请求页面 → 抽取内联 JSON / 私有 API → 组装直链"，这套思路可以用 Kotlin 完整复刻，且没有 Python 运行时负担。
2. **cobalt 的协议足够简单**（`POST /api/json`），把它作为"远端兜底"通道，用户可自建，规避单一本地实现被风控击穿的风险。
3. **Cookie 是唯一能拿到原画质的合法途径**（Instagram / 小红书 / Facebook），必须由用户自己提供，应用只做本地存储与注入。

## 1.3 各平台解析要点（调研结论）

| 平台 | 可用入口 | 关键字段 | 是否需要登录 |
| --- | --- | --- | --- |
| **X (Twitter)** | `cdn.syndication.twimg.com/tweet-result?id={id}&token={token}`，token = `((id/1e15)*π).toString(36)` 去掉 `.` 与 `0` | `mediaDetails[].video_info.variants[]`、`photos[]` | 否 |
| **Instagram** | 免登录：`/p/{code}/embed/captioned/`；登录态：`/p/{code}/?__a=1&__d=dis` | `video_url`、`display_url`、`video_versions[]`、`image_versions2.candidates[]` | 多图/高清需要 |
| **小红书** | 笔记详情页内联 `window.__INITIAL_STATE__` | `stream.h264[].masterUrl`、`imageList[].urlDefault`（去 `?imageView2` 即原图） | 完整图集需要 |
| **Facebook** | `m.facebook.com` 移动版页面 | `hd_src_no_ratelimit` > `hd_src` > `sd_src_*` > `playable_url` > `og:video` | 是（否则只有低清/封面） |
| **TikTok** | 详情页内联 `__UNIVERSAL_DATA_FOR_REHYDRATION__` | `bitRateInfo[].PlayAddr.Url`、`playAddr`、`imagePost.images[]` | 否 |
| **抖音** | 旧接口 `iesdouyin.com/web/api/v2/aweme/iteminfo/` + 详情页 `_ROUTER_DATA` | `video.play_addr.url_list`（`playwm`→`play` 去水印）、`images[]` | 否 |
| **B站** | `api.bilibili.com/x/web-interface/view` + `playurl`（需 **WBI 签名**） | `durl[].url`（MP4/FLV）或 `dash.video[]/audio[]` | 高码率需要 |
| **微博** | `m.weibo.cn/detail/{id}` 内联 `$render_data` | `page_info.urls.mp4_720p_mp4`、`pics[].large.url` | 否 |
| **YouTube** | Piped / Invidious 公开实例 API，或自建 cobalt | `videoStreams[].url`、`audioStreams[].url` | 否（经中继） |

## 1.4 与下载侧的衔接

解析产物统一为 `MediaItem`：

```kotlin
MediaItem(
    url = "直链或 m3u8/mpd 清单",
    kind = VIDEO / IMAGE / AUDIO,
    quality = "1080p",
    headers = { "Referer": "..." },   // 防盗链必需
    isPlaylist = false,               // m3u8 → true
    audioUrl = "...",                 // DASH 分离音轨
    needsRemux = false
)
```

下载器只看这一层结构，不感知上游平台差异 —— 新增平台时只需新增一个解析器，下载与 UI 侧零改动。

## 1.5 合规与可持续性说明

- 本应用只下载**用户自己复制的公开内容链接**，不提供批量抓取、不绕过付费墙。
- Cookie 由用户自行提供、仅存本机，不参与任何外发请求。
- 各平台接口随时可能变更，因此每个解析器都保留 `warning` 字段用于向用户透明提示降级情况，且解析器可独立更新（SPI 注册表）。
- 远端解析服务的地址可由用户替换，应用不硬编码任何第三方服务依赖。
