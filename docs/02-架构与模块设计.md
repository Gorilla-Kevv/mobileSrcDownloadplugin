# 二、整体架构与页面 / 模块设计

## 2.1 目标平台

应用内置以下平台的识别与解析（可在设置页按需开关监听范围）：

| 平台 | id | 域名 / 短链 | 登录态 | 支持形态 |
| --- | --- | --- | --- | --- |
| Instagram | `instagram` | instagram.com、instagr.am | 多图/高清需要 | 视频、单图、多图、Reels |

| 小红书 | `xiaohongshu` | xiaohongshu.com、xhslink.com | 完整图集需要 | 视频、图集 |
| Facebook | `facebook` | facebook.com、fb.watch | 是 | 视频、图片 |
| TikTok | `tiktok` | tiktok.com、vm.tiktok.com | 否 | 视频、图文 |
| 抖音 | `douyin` | douyin.com、v.douyin.com | 否 | 视频、图集 |
| 哔哩哔哩 | `bilibili` | bilibili.com、b23.tv | 高码率需要 | 视频（DASH / FLV） |
| 微博 | `weibo` | weibo.com、m.weibo.cn、t.cn | 否 | 视频、九图 |

> 平台定义集中在 `parser` 模块的 `Platform` 枚举中，新增平台 = 新增枚举项 + 新增一个 `PlatformParser` 实现并注册，其余模块零改动。

## 2.2 整体架构

采用**三模块分层 + 单向依赖**，解析与下载能力完全脱离 UI：

```
┌──────────────────────────────────────────────────────────────┐
│  :app  （UI 层 · Jetpack Compose + 悬浮窗 + 剪贴板通道）        │
│  ├─ ui/          首页 / 下载 / 设置 + 毛玻璃组件                │
│  ├─ floatwindow/ 悬浮球 + 半透明毛玻璃弹窗（WindowManager）     │
│  ├─ clip/        剪贴板监听、借道 Activity、无障碍、分享入口     │
│  └─ data/        设置（DataStore）、平台 Cookie                 │
└───────────────┬──────────────────────────┬───────────────────┘
                │                          │
      ┌─────────▼──────────┐     ┌─────────▼──────────┐
      │  :downloader       │────▶│  :parser           │
      │  下载引擎（自研）   │     │  解析内核（纯 JVM） │
      │  ├ 队列/并发/重试   │     │  ├ URL 归一化      │
      │  ├ 断点续传         │     │  ├ 平台路由（SPI） │
      │  ├ HLS/AES/合并     │     │  ├ 各平台解析器     │
      │  ├ DASH 音视合并    │     │  ├ 远端兜底         │
      │  ├ MediaStore 入库  │     │  └ m3u8 解析        │
      │  └ 前台服务/通知    │     └────────────────────┘
      └────────────────────┘
```

**分层原则：**

- `:parser` 是**纯 Kotlin/JVM 模块**，不引用任何 Android API —— 可以直接在 JVM 上跑单测，也便于单独升级解析器而不动 UI。
- `:downloader` 依赖 `:parser`，对上只暴露 `DownloadController` 一个门面。
- 模块间通过**数据模型**（`MediaItem` / `TaskEntity`）通信，不互相持有状态。

### 运行时分层

```
[ 通道层 ]  剪贴板监听 / 无障碍 / 系统分享 / 手动粘贴
     │  LinkCenter（去重 + 汇聚）
     ▼
[ 解析层 ]  ParserEngine → PlatformRegistry → 具体 PlatformParser
     │  ParseResult
     ▼
[ 呈现层 ]  悬浮窗毛玻璃弹窗 / 首页结果卡
     │  用户选择清晰度
     ▼
[ 下载层 ]  DownloadController → DownloadEngine（队列）→ 任务状态机
     │  MediaStore 写入 + 通知
     ▼
[ 数据层 ]  SQLite 任务表 + DataStore 设置 + SP Cookie
```

## 2.3 页面与功能模块

### 页面（3 个主页面 + 2 个隐形页面）

| 页面 | 职责 | 关键能力 |
| --- | --- | --- |
| **首页 `HomeScreen`** | 手动兜底入口 + 权限引导 + 平台总览 | 粘贴/读取剪贴板并解析；展示封面、清晰度选择、下载按钮；悬浮窗与无障碍权限一键跳转 |
| **下载页 `DownloadsScreen`** | 任务管理 | 实时进度/速度、暂停/继续/重试/删除、完成后调用系统播放器打开 |
| **设置页 `SettingsScreen`** | 行为与能力配置 | 悬浮窗开关、自动弹窗、仅 Wi-Fi、并发数、监听范围、平台 Cookie、远端解析服务 |
| **`ClipGateActivity`**（透明） | 借道前台读取剪贴板 | 100~300ms 内完成读取并退出，用户无感知 |
| **`ShareTargetActivity`**（隐形） | 系统分享入口 | 接收 `ACTION_SEND` 文本，直达解析 |

### 功能模块

| 模块 | 主要类 | 说明 |
| --- | --- | --- |
| 链接中枢 | `LinkCenter` | 汇聚 4 个通道、去重（15s 窗口）、缓存最近一次解析结果 |
| 剪贴板通道 | `ClipboardMonitor` | 监听 + 前台态读取，受限时自动让位给其它通道 |
| 借道通道 | `ClipGateActivity` | 解决 Android 10+ 后台剪贴板限制 |
| 无障碍通道 | `ClipAccessibilityService` | 扫描窗口文本节点提取链接，仅本地匹配 |
| 分享通道 | `ShareTargetActivity` | 成功率最高的通道，无权限依赖 |
| 悬浮窗 | `FloatingWindowService` | 悬浮球（可拖动、保存位置）+ 毛玻璃弹窗（自动收起倒计时） |
| 解析内核 | `ParserEngine` / `PlatformRegistry` / `*Parser` | 短链展开 → 平台判定 → 解析 → 三级降级 |
| 下载引擎 | `DownloadController` / `DownloadEngine` | 队列、并发、断点续传、重试退避、HLS/DASH 合并 |
| 存储 | `TaskDatabase` / `MediaStoreWriter` | 任务表持久化；Android 10+ 分区存储免权限入库 |
| 通知 | `DownloadNotifier` | 进度通知（低频通道）+ 完成/失败提醒 |

## 2.4 关键设计取舍

| 取舍 | 选择 | 原因 |
| --- | --- | --- |
| UI 框架 | Jetpack Compose + Material3 | 弹窗/结果卡有大量条件渲染与动画，Compose 代码量显著更低 |
| 悬浮窗渲染 | WindowManager + ComposeView + 自造 LifecycleOwner | 悬浮窗无 Activity 托管，需自行提供 `LifecycleOwner` / `SavedStateRegistryOwner`（见 `OverlayLifecycleOwner`） |
| 持久化 | 手写 SQLite（非 Room） | 任务表结构极稳，省掉注解处理器开销；且进度高频写入可只更新必要列 |
| 配置存储 | DataStore | 与 Compose 的 Flow 天然契合，设置改动可即时热更新到解析/下载内核 |
| 并发模型 | Coroutine Channel + N 个 worker | 比手写线程池更容易做取消与重试，且天然结构化并发 |
