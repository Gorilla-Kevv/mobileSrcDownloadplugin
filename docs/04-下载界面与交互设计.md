# 四、下载界面设计

下载能力分为**悬浮弹窗**与**应用内页面**两套界面，前者负责"零打断的即时下载"，后者负责"完整管理"。

## 4.1 悬浮窗毛玻璃弹窗（核心形态）

### 视觉规格

| 项 | 规格 |
| --- | --- |
| 容器 | 全屏 `WindowManager` 覆盖层，`TYPE_APPLICATION_OVERLAY` |
| 背景模糊 | Android 12+：`FLAG_BLUR_BEHIND` + `setBlurBehindRadius(28)`（系统级真实背景模糊） |
| 低版本降级 | 半透明深色遮罩 `0xAA0A0E1A`，观感一致但无实时模糊 |
| 卡片 | 圆角 24dp；底色 `GlassBase @ 74%`；1dp 白色高光描边 `alpha 0.16`；阴影 24dp |
| 进场动画 | `fadeIn + slideInVertically`（从下方 1/3 处滑入），出场反向 |
| 自动收起 | 默认 15s 倒计时（右上角显示剩余秒数）；用户任何交互都重置计时 |
| 点击外部 | 收起弹窗，不取消已加入的下载 |

### 信息层级

```
┌─────────────────────────────────────────┐
│  ▢ 小红书                       12s  ✕  │   ← 平台标识 / 倒计时 / 关闭
│     已解析 9 个资源                       │
├─────────────────────────────────────────┤
│  ┌────┐  秋日穿搭合集                    │   ← 封面 + 标题（2 行截断）
│  │缩略│  @某某                           │
│  │ 图 │  原图 · 2.4 MB · 1080×1440       │   ← 当前选中资源的副标题
│  └────┘                                 │
│  ⚠ 仅获取到封面图，完整图集需要登录态     │   ← 降级提示（琥珀色）
├─────────────────────────────────────────┤
│  [视频 · 原画质] [图片 · 原图 1] [图片…] │   ← 清晰度/资源横向选择
├─────────────────────────────────────────┤
│  在应用内打开              [ ⤓ 下载 ]    │
└─────────────────────────────────────────┘
```

### 悬浮球

- 56dp 圆形按钮，靛蓝底 + 白色高光描边；
- 可拖动，位置持久化到 DataStore，下次启动原地恢复；
- 有未处理链接时描边变绿并显示 `!`，无打扰地提示；
- 点击 → 借道读取剪贴板并立即解析。

### 状态机

```
Hidden ──捕获链接──▶ Loading ──成功──▶ Ready ──下载──▶ (入队后 900ms 自动收起)
                        │                 │
                        └──失败──▶ Failed ──重试──▶ Loading
```

## 4.2 应用内下载界面

### 首页结果卡

与弹窗信息一致，但可横向滚动切换清晰度并直接下载；解析失败时展示红色错误卡 + 可操作建议。

### 下载管理页

| 元素 | 说明 |
| --- | --- |
| 任务行 | 标题（单行截断）+ 状态文案 + 状态胶囊 |
| 进度 | `LinearProgressIndicator`（6dp，圆角），下载中/等待中显示 |
| 状态文案 | `12.4 MB / 48.1 MB · 2.1 MB/s`；完成时 `已完成 · 48.1 MB`；失败时展示错误原因 |
| 操作 | 打开（仅完成态）/ 暂停 / 继续 / 删除 |
| 状态色 | 下载中=靛蓝、暂停=琥珀、完成=绿、失败=红 |
| 空状态 | "还没有下载任务 / 复制一条链接，悬浮窗会提示下载" |

**进度数据来源**：列表快照来自 SQLite（保证刷新与重启后一致），实时进度来自引擎的 `SharedFlow<ProgressEvent>`（保证流畅），两者叠加。列表按 1s 周期刷新快照。

### 通知

- 前台服务常驻通知（低频通道，不打扰）：显示"正在进行 N 个下载任务"；
- 每个任务一条进度通知（复用同一 notificationId 避免刷屏）：`标题 + 百分比 + 速度`；
- 完成/失败后转为可清除的结果通知。

## 4.3 下载引擎的界面无关契约

```
DownloadController.enqueue(MediaItem, Platform, title) -> taskId
DownloadController.pause / resume / cancel(taskId)
DownloadController.repository().tasks  : StateFlow<List<TaskEntity>>
DownloadController.engine().progress   : SharedFlow<ProgressEvent>
```

界面只需要这 4 个入口，不感知断点续传、分片合并、重试等任何内部细节。

## 4.4 任务类型与落盘

| 类型 | 判定 | 处理 | 产物 |
| --- | --- | --- | --- |
| `SINGLE` | 普通直链 | Range 断点续传，单文件写入 | 原格式（mp4/jpg…） |
| `HLS` | `container=m3u8` 或 `isPlaylist` | 并发拉分片 → AES-128 解密 → 顺序拼接 → 尽力 remux | `.mp4`（remux 失败则 `.ts`） |
| `DASH` | 存在分离 `audioUrl` | 视频轨/音频轨分别下载 → `MediaMuxer` 合并 | `.mp4` |

落盘：Android 10+ 通过 `MediaStore` 写入 `Movies/ClipDown`、`Pictures/ClipDown`、`Music/ClipDown`（**不需要存储权限**）；Android 9- 写入公共 Downloads 目录。
