# 06 · 博主主页功能设计（解析 → 独立页面 → 自由下载）

> 目标：复制博主主页链接后，在**应用内新建的独立页面**完整展示该博主主页内容（笔记列表、标题、封面、正文），
> 并允许用户自由挑选下载。仅在本应用内使用，不涉及对外分享。
>
> 状态：架构与页面已落地（阶段 36）；解析器按平台逐个接入，见文末《平台数据源与接入状态》。

---

## 一、为什么单开一条链路（而不是塞进现有解析）

现有链路是**单篇作品**模型：`ParseResult = 1 个作品 + N 个媒体`。主页是**集合**模型：
`1 个作者 + N 篇笔记`，而且列表页通常只有封面和标题，正文与媒体要点开单篇才有。

把主页塞进现有链路的后果：
- 会被"远端兜底 / 通用网页解析"当成一篇作品去抓 → 抓回一页垃圾（历史上 IG 就踩过这个坑）；
- 一次要展开 N 篇的媒体 → 请求风暴，必然触发风控。

因此主页是一条**平行的独立链路**：

```
单篇链路：UrlUtil.detectPlatform → PlatformRegistry(PlatformParser) → ParseResult(media[])
主页链路：ProfileUrls.match       → ProfileRegistry(ProfileParser)  → ProfileResult(posts[])
```

两条链路共用 `ParseContext`（HTTP / Cookie / WebView），但**降级策略互不干扰**。

## 二、链接识别（最容易出错的一环）

`ProfileUrls.match(url)` 按平台显式规则识别，核心是**保留段白名单**：
Instagram 的 `/p/xxx`（作品）与 `/<username>`（主页）只差一段路径，
X 的 `/status/xxx` 同理 —— 命中保留段一律判为作品页。

| 平台 | 主页形态 | handle 语义 |
|---|---|---|
| 小红书 | `xiaohongshu.com/user/profile/<userId>` | 用户 ID |
| Instagram | `instagram.com/<username>` | 用户名 |
| X | `x.com/<username>` | 用户名 |
| 微博 | `weibo.com/u/<uid>`、`m.weibo.cn/u/<uid>` | uid |
| 哔哩哔哩 | `space.bilibili.com/<mid>` | mid |
| 抖音 | `douyin.com/user/<sec_uid>` | sec_uid |
| TikTok | `tiktok.com/@<user>` | 用户名 |
| YouTube | `youtube.com/@<handle>`、`/channel/<id>`、`/c/<name>` | handle/id |

`ParserEngine.linkKind(url)` 返回 `PROFILE / POST / UNKNOWN`，UI 据此决定"打开主页"还是"走单篇解析"。

## 四、交互流程

### 主流程（复制链接 → 主页 → 下载）

1. 用户在平台 App 里复制博主主页链接（分享文案里通常夹带中文，`UrlUtil.extractFirst` 负责召回）。
2. 剪贴板被识别 → 悬浮气泡提示 → 点气泡 → `ParserEngine.linkKind()` 判定为 `PROFILE`
   → 走主页链路解析 → 气泡/卡片显示「博主 XXX · N 篇笔记」→「打开主页」。
3. 进入**主页页**：先显示博主信息卡（头像/昵称/简介/统计），笔记网格随后铺开。
4. 用户在网格里勾选（可「全选」「清空」，或先按 视频/图文 筛选再全选）。
5. 点「下载所选 N 项」→ 逐篇解析 → 媒体入队 → 吸底条回显进度「正在解析 3/12」→ 完成后提示
   「已加入下载队列：N 篇」。
6. 也可点单个封面打开详情面板 → 看正文 → 「下载本篇」（面板内可逐项勾选媒体）。

### 状态与边界

| 状态 | 表现 |
|---|---|
| 加载中 | 转圈 + "主页数据由平台前端渲染，首次打开可能需要十几秒" |
| 加载失败 | 错误提示条 + 「重试」；文案区分"需登录态"（提示去设置补 Cookie）与"结构变化" |
| 空主页 | 明确报错"未能提取到笔记列表"，**不返回空主页**（避免用户以为博主没内容） |
| 笔记数过多 | 单次最多展示 60 篇，超出时提示"仅展示前 60 篇" |
| 部分失败 | 批量下载时逐篇计数，完成后提示"已加入 X 篇，Y 篇解析失败" |

### 与下载页的衔接

每篇笔记以 **`sourceUrl = 该笔记链接`** 入队 → 下载页会自动把它们**按笔记分组**
（复用现有图集分组逻辑），用户能看清"哪张图属于哪篇"。

## 六、平台数据源与接入状态

主页数据的获取难度远高于单篇：多数平台的主页列表**不是 SSR**，而是页面 JS 带签名请求后渲染。

| 平台 | 数据来源 | 是否需登录/签名 | 接入状态 |
|---|---|---|---|
| 小红书 | 桌面 UA + Cookie 取 SSR 首屏；分页走 WebView 内 XHR 钩子回收 `user_posted` 响应（需 `x-s` 签名，页面自己发） | 需登录态 | 已接入并实测（阶段 37-40，单账号可翻到 200+ 篇） |
| Instagram | ①`i.instagram.com/api/v1/users/web_profile_info/?username=`（需 Cookie + `x-ig-app-id`）②主页 HTML 的 `og:*` + 帖子链接扫描 ③WebView 渲染兜底 | **需登录**（免登录只返回登录墙，2026-10 实测 200/637KB 但无 og、无帖子链接） | 代码与单测已落地（阶段 41），**待有效 Cookie 实测校准**；全程受 `IgRiskGuard` 冷却保护 |
| X | `syndication.twitter.com/srv/timeline-profile/screen-name/<handle>` 的 `__NEXT_DATA__`（与单篇 syndication 同族） | **免登录** | 已接入并实测（阶段 41：100 条时间线 + 点开视频实际下载成功） |
| 微博 | `m.weibo.cn/api/container/getIndex` | 免登录（但会风控） | 待接入 |
| 哔哩哔哩 | `x/space/wbi/arc/search`（需 WBI 签名，项目已有签名代码） | 免登录 | 待接入 |
| 抖音 / TikTok | 页面签名接口 | 需登录 | 待接入 |
| YouTube | `youtubei/v1/browse` | 免登录（需 key） | 待接入 |

**接入一个平台的步骤**（机械操作，无需改 UI）：
1. 新建 `XxxProfileParser : ProfileParser`，在 `parseProfile()` 里取数据、映射成 `ProfilePost` 列表；
2. 加到 `ParserEngine.defaultProfileParsers()`；
3. 在 `parser/src/test/resources/` 放一份响应/渲染快照，写对应用例。

> 注：`ProfileUrls` 早已支持 IG / X 的 `/<handle>` 识别（保留段白名单），接入新平台通常**不需要改路由与 UI**。
