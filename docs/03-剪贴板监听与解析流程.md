# 三、剪贴板监听与网址解析流程

## 3.1 先说清楚一个硬约束

**Android 10（API 29）起，系统禁止后台应用读取剪贴板**——只有处于前台的应用（或默认输入法）才能拿到 `ClipboardManager.primaryClip`。

这意味着"后台常驻监听剪贴板"在标准 API 下**不可能 100% 可靠**。因此本应用不依赖单一通道，而是设计了 **四通道并行 + 自动让位** 的方案，任一通道可用即触发识别。

## 3.2 四通道设计

| 通道 | 实现 | 触发时机 | 可靠性 | 需要权限 |
| --- | --- | --- | --- | --- |
| **前台剪贴板** | `ClipboardManager.OnPrimaryClipChangedListener` | App 在前台时复制 | 高（但仅前台） | 无 |
| **借道前台** | `ClipGateActivity`（透明 Activity） | 点击悬浮球 / 通知 / 无障碍捕捉到疑似复制 | 高 | 无 |
| **无障碍监听** | `ClipAccessibilityService` 扫描窗口文本 | 在任意 App 中复制分享文案 | 中（依赖页面文本可见） | 需手动开启无障碍 |
| **系统分享** | `ShareTargetActivity` (`ACTION_SEND`) | 用户主动分享到本应用 | **最高** | 无 |

```
                    ┌──────────── 前台剪贴板（App 可见时）
                    │
任意 App 复制 ──┬──▶├──────────── 无障碍（扫描窗口文本）
                │   │
                │   ├──────────── 借道 Activity（临时拉前台后读取）
                │   │
                └──▶└──────────── 系统分享（用户主动）
                                    │
                                    ▼
                          LinkCenter（去重 15s）
                                    │
                                    ▼
                          ParserEngine.parse()
                                    │
                    ┌───────────────┴───────────────┐
                    ▼                               ▼
              悬浮窗毛玻璃弹窗                   首页结果卡片
```

### 借道前台（关键技巧）

`ClipGateActivity` 是一个主题全透明、无动画、不进最近任务的 Activity：

1. 悬浮球被点击 → `startActivity(ClipGateActivity)`；
2. `onResume()` 中读取剪贴板（此刻进程处于前台，读取合法）；
3. 提交到 `LinkCenter` 后 120ms 内 `finishAndRemoveTask()`，用户完全无感知。

### 去重策略

同一条链接在 **15 秒**内只触发一次（`LinkCenter.DEDUP_WINDOW_MS`），
避免用户在 Instagram / 小红书里反复复制导致弹窗刷屏；用户主动操作（点击悬浮球、分享、手动解析）使用 `force = true` 跳过去重。

## 3.3 URL 提取与归一化

剪贴板文本形态极其多样（中文文案 + emoji + 短链 + 无协议头），因此分两步处理：

1. **宽松召回**（`UrlUtil.extractAll`）
   - 先做文本预处理：剥离零宽字符、还原 `&amp;`、`\/` 转义、换行转空格；
   - 匹配 `https?://...` 与 `www....`；
   - 再匹配"裸域名"（`xhslink.com/a/xxx`、`v.douyin.com/xxx`），自动补 `https://`；
   - 尾部排除中文标点，避免把文案一起吞进来。

2. **归一化收敛**（`UrlUtil.normalize`）
   - IDN/Punycode 转换、统一末尾斜杠；
   - 剔除跟踪参数（`igshid`、`utm_*`、`ref`、`spm_id_from`、`vd_source`、`share_*` …）；
   - 归一化后同一条链接的不同分享形式会收敛为同一个 key，保证去重有效。

## 3.4 解析主流程

```
输入 URL
  │
  ├─(1) 平台判定：host 精确/后缀匹配 → 路径特征兜底（/p/ /reel/ /status/ /explore/ …）
  │      不在监听范围 → 直接放弃（不发请求）
  │
  ├─(2) 短链展开：xhslink / t.co / youtu.be / b23.tv / v.douyin.com / vm.tiktok.com
  │      优先 HEAD 取 Location，失败则 GET 跟随重定向取 finalUrl；展开后重新判定平台
  │
  ├─(3) 本地 / 公开接口解析（PlatformRegistry 路由到对应 PlatformParser）
  │      ├─ 有 Cookie → 走登录态接口拿原画质
  │      └─ 无 Cookie → 走免登录入口（embed 页 / syndication / 移动版页面）
  │
  ├─(4) 失败 → 远端兜底（用户自建 cobalt / yt-dlp 服务，POST /api/json）
  │
  ├─(5) 仍失败 → 通用网页解析（og:video / og:image / <video src>）
  │
  └─(6) 全部失败 → 抛 ParseException（携带 retryable 标记与人类可读原因）
```

### 解析器 SPI

```kotlin
interface PlatformParser {
    val platform: Platform
    val id: String
    fun canHandle(url: String): Boolean
    fun parse(url: String, ctx: ParseContext): ParseResult
}
```

`PlatformRegistry` 在内核启动时注册全部实现：
`Xiaohongshu / Instagram / X / Facebook / Tiktok / Douyin / Bilibili / Weibo / Youtube / Generic`。
新增平台只需新增实现类并加进 `ParserEngine.defaultParsers()`。

### 状态与提示

解析结果不只返回数据，还携带**降级原因**（`ParseResult.warning`）与**失败语义**（`ParseException.retryable`），
UI 据此给出可操作的提示，例如：

- `"Instagram 已限制免登录访问，当前仅能获取缩略图。补充 Cookie 或开启远端解析可获得原画质"`
- `"该笔记需要登录态，请在设置中补充小红书 Cookie 或开启远端解析"`

## 3.5 触发弹窗的判定时机

为避免"复制任何东西都弹窗"，只有同时满足以下条件才展示弹窗：

1. 文本中召回出了 URL；
2. URL 归一化后能匹配到受支持平台 (`UrlUtil.detectPlatform`)；
3. 该平台在用户设置的监听范围内 (`ParserConfig.isEnabled`)；
4. 去重窗口内没有重复。

弹窗出现后**立即异步解析**（不阻塞 UI），先用平台名 + "正在解析"占位，解析完成后原地替换为结果或失败态。
